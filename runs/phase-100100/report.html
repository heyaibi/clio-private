01

Concurrent first observes race: create is check-then-insert outside a transaction

Important
Why it matters
belief_observe decides create-vs-append with a read (find_belief_by_proposition), then inserts in a separate transaction. Two observes of the same proposition that both read 'missing' both run the create path; the second violates the unique index and returns InvalidArgument instead of appending. The phase failure table expects concurrent observes to serialize as append.
Impact if unaddressed
A legitimate second observation is dropped as an error under concurrency on a new belief identity (no data corruption, but lost evidence and a spurious failure).
Evidence
crates/clio-belief/src/observe.rs:223-268; crates/clio-store/src/sqlite_belief.rs:74-92; crates/clio-store/src/belief_store.rs:135-152; sql/001_core.sql beliefs_bank_id_proposition_key_uix
Confidence
High

Proposed fix (not yet applied)

Make create-or-append atomic: either INSERT ... ON CONFLICT DO NOTHING then append when zero rows inserted, or catch the duplicate-key error and re-run the append branch, inside the store transaction.

Considered and dismissed

  • decide() losing its category gate: verification shows the whitelist lived in decide_raw via typed Candidate parsing, not in decide; the refactor to decide_ungated is behavior-preserving and all admission tests pass.
  • ConfidenceEntry/BeliefObject array-order current_confidence vs as_of ordering: stored histories are loaded ORDER BY as_of, so current_* is correct on every read path; only a hand-built out-of-order BeliefObject could differ, and no production caller does that.
  • Cross-subject evidence mixing on a shared proposition key: identity is (bank_id, proposition_key) by documented design, and subject_id only selects the DEK; bank remains the isolation boundary.
  • No DB trigger enforcing append-only history: the trait exposes only append/create with no UPDATE/DELETE path, so the API boundary is append-only.
  • Schema version bump 4->5 with fail-closed ConfigCorrupt on non-empty legacy beliefs: the phase explicitly permits fail-closed for pre-epistemic rows and the tables are undeployed.
  • roadmap-isolation: no references to roadmap/, phase numbers, or crates.md found in crates/ or sql/.
