01

Broken JSON Schema $ref pointer in published profile_json_schema and missing definition in MCP tool schemas

Important
Why it matters
MCP clients and tooling validating tool calls or config against profile_json_schema fail with PointerToNowhere errors because the $ref points to /properties/mission/x-mission-entry which does not exist. Furthermore, x-mission-entry is missing from the MCP tool schemas.
Impact if unaddressed
Any standard JSON Schema validator fails on tool parameter validation for retention_profile_set and admit_preview_batch.
Evidence
crates/clio-config/src/retention_schema.rs:105, 112, 123. Running python jsonschema.validate() produces '_WrappedReferencingError PointerToNowhere: /properties/mission/x-mission-entry does not exist'.
Confidence
High

Proposed fix (not yet applied)

Move x-mission-entry into definitions or under mission.properties, update the $ref paths to point correctly to the definition, and ensure schema_retention_defs embeds the definition.

02

Secret-bearing mission patterns are not rejected at set time and persist unmasked in profile configuration

Important
Why it matters
Section 7 Security Constraints explicitly requires: 'Never commit secrets; mission examples containing secret patterns are rejected with guidance to use hygiene tooling instead.' Unchecked examples store credentials in plaintext on disk.
Impact if unaddressed
Users or tools providing secret patterns in keep/drop examples cause raw API keys or passwords to be persisted in profiles.json.
Evidence
crates/clio-config/src/retention_mission.rs:143-215 (RetentionMission::validate). Executing 'am retention set' with an api_key string succeeds and writes the unmasked credential to disk.
Confidence
High

Proposed fix (not yet applied)

Add secret pattern detection using clio_config::secret to RetentionMission::validate(), returning an InvalidArgument error guiding the user to hygiene tools.
