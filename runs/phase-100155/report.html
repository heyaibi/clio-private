02

Dry-run reports success on already-discarded items

Important
Why it matters
Destructive confirmation dry-run (§4.9.2) should validate whether a discard will succeed. Because get_item_identity does not filter discarded_at IS NULL, an unconfirmed call on an already-discarded item returns DryRun(identity) indicating it would be discarded, but the subsequent confirmed call fails with InvalidArgument.
Impact if unaddressed
Inconsistency between dry-run and execution paths; false confidence given to callers during dry run.
Evidence
crates/clio-write/src/discard.rs:160-166: `let identity = args.store.get_item_identity(bank, args.item_id)?.ok_or_else(...); DiscardOutcome::DryRun(identity)` combined with `SELECT category, epistemic_kind FROM items WHERE id = ?1 AND bank_id = ?2` in crates/clio-store/src/sqlite_discard.rs:36.
Confidence
High

Proposed fix (not yet applied)

Update get_item_identity SQL to include `AND discarded_at IS NULL`, or have ItemIdentity include a discarded flag so the dry-run path rejects already-discarded items with the same error as confirmed discard.

03

Concurrent discard race returns ErrorCode::Internal

Minor
Why it matters
In a race condition where two callers attempt to discard the same item concurrently, both may pass the initial lookup, but only one will update the row. The loser encounters n == 0 and receives an Internal server error instead of the expected InvalidArgument (already discarded) error.
Impact if unaddressed
Surfaces misleading 500/Internal errors to operators or callers under concurrent access.
Evidence
crates/clio-store/src/sqlite_discard.rs:100-105: `if n == 0 { return Err(AmError::new(ErrorCode::Internal, "discard update matched zero rows")); }`
Confidence
High

Proposed fix (not yet applied)

On n == 0, query the item again to confirm if it was discarded by a concurrent transaction, and return ErrorCode::InvalidArgument if so.
