01

Read-only clio status creates a 512KB database and runs schema migrations on nonexistent SQLite path

Important
Why it matters
The command is explicitly specified as read-only with a hard guarantee that it never mutates or writes to disk (AC-100362-04). A user inspecting status with a misspelled or not-yet-created database path will find a brand new 512KB SQLite database populated on their filesystem.
Impact if unaddressed
Violates non-mutation contract (§1, §2, §7, AC-100362-04). If clio status is run by monitoring daemons before initialization, it prematurely boots schemas and creates unexpected files.
Evidence
Running `target/debug/clio status --backend sqlite --db /tmp/nonexistent-test-123456.db` creates `/tmp/nonexistent-test-123456.db` (512,000 bytes) on disk. In `crates/clio-lib/src/status_cli.rs:207`, `SqliteStore::open(Path::new(&resolved.url), kms)` is called without checking `Path::new(&resolved.url).exists()`.
Confidence
High

Proposed fix (not yet applied)

In `open_chosen` (`crates/clio-lib/src/status_cli.rs:207`), check `Path::new(&resolved.url).exists()` before calling `SqliteStore::open`. If the file does not exist, return `Err(AmError::new(ErrorCode::NotFound, "database file does not exist"))`, causing status to report a degraded verdict (exit 1) without creating any files.
