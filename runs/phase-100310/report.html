01

48 binary LLVM profiling dumps (.profraw) staged in Git index

Important
Why it matters
Committing binary build/profiling artifacts bloats repository history, pollutes git status/diffs, and breaks repository hygiene standards.
Impact if unaddressed
18.5 MB of unneeded binary machine-specific profile data is staged in git and would be committed to the repository.
Evidence
git diff --cached --name-only | grep '\.profraw$' lists 48 files in crates/clio-lib/ (e.g., crates/clio-lib/default_12130406370214325728_0_89478.profraw).
Confidence
High

Proposed fix (not yet applied)

Unstage and delete all crates/clio-lib/*.profraw files. Add `*.profraw` to `.gitignore`. In `crates/clio-lib/tests/default_db_path_test.rs`, ensure subprocesses run with LLVM_PROFILE_FILE directed to a temp dir or filtered from workspace tracking.

02

Config system defaults hardcode backend: sqlite ignoring scheme inference

Important
Why it matters
When DATABASE_URL=postgres://... is configured, the CLI infers Postgres, but effective config defaults backend to sqlite, causing StoreOpenOptions::from_effective to open SQLite rather than Postgres.
Impact if unaddressed
Downstream phases relying on StoreOpenOptions::from_effective (such as Phase 100330 am setup, guaranteed in §12) or inspecting config_get("backend") observe a backend/database mismatch where store.database_url points to Postgres while backend remains sqlite.
Evidence
crates/clio-config/src/config/merge.rs:35-43 calls resolve_database(get, None, None) which infers backend="postgres", but line 39 hardcodes `"backend": "sqlite"` in system_defaults.
Confidence
High

Proposed fix (not yet applied)

Update `system_defaults` in `crates/clio-config/src/config/merge.rs` to set `"backend": resolved.backend` instead of `"backend": "sqlite"`, and ensure `Runtime::apply_process_env` sets `backend` when inferred from `DATABASE_URL`.
