01

Test prompt_tty_false_is_non_interactive_and_true_reads_stdin hangs indefinitely on unclosed stdin

Important
Why it matters
Running make check or cargo test in any interactive terminal or runner with inherited, unclosed stdin hangs indefinitely on read_line, freezing CI / local test runs.
Impact if unaddressed
Prevents automated or interactive test runs from completing without explicit </dev/null stdin redirection.
Evidence
crates/clio-lib/src/compose_cli_fail_tests.rs:144 calls prompt_tty(true), invoking std::io::stdin().read_line(). Task-56 running make check hung for over 6 minutes until cancelled.
Confidence
High

Proposed fix (not yet applied)

Do not call prompt_tty(true) on process stdin in unit tests. Parameterize the reader in prompt_tty(is_tty, reader) or test read_answer with in-memory buffers.

02

Avoidable panics in file backup and .env permission error paths

Important
Why it matters
Production CLI commands should return Result rather than crashing with unhandled thread panics on filesystem errors.
Impact if unaddressed
If a user runs am compose up on a read-only directory, a full disk, or a filesystem that does not support Unix file modes (exFAT/FAT32/SMB), the command crashes with a panic.
Evidence
crates/clio-lib/src/compose_assets.rs:144 uses .expect("back up user-edited compose file"); crates/clio-lib/src/compose_env.rs:85 uses .expect("restrict generated .env permissions").
Confidence
High

Proposed fix (not yet applied)

Propagate io::Error as Result<(), String> in backup_edited and restrict_owner_only, returning clear error messages if backup or permission changes fail.

04

Non-atomic .env file creation introduces brief world-readable window before chmod

Minor
Why it matters
Security guidelines require owner-only permissions on sensitive files. Writing then chmodding leaves a race window where other local users can open the file.
Impact if unaddressed
Other local processes or users on a multi-user machine could open .env before restrict_owner_only executes.
Evidence
crates/clio-lib/src/compose_env.rs:72-73: std::fs::write(&path, contents) followed by restrict_owner_only(&path).
Confidence
High

Proposed fix (not yet applied)

Use std::fs::OpenOptions with Unix mode(0o600) to create the file atomically with mode 0600 on Unix platforms.
