01

IndexStore search primitives return 1 hit when limit is 0

Important
Why it matters
Callers requesting zero results (e.g. for existence checks or pagination probes) receive an unexpected match.
Impact if unaddressed
Violates expected query limit semantics for callers directly invoking IndexStore trait methods.
Evidence
crates/clio-store/src/sqlite_index.rs:148, crates/clio-store/src/sqlite_index.rs:187, crates/clio-store/src/postgres_index.rs:146, crates/clio-store/src/postgres_index.rs:195
Confidence
High

Proposed fix (not yet applied)

Add an early check `if limit == 0 { return Ok(Vec::new()); }` at the start of dense_search and lexical_search on both SqliteStore and PostgresStore.

02

HTTP client connects only to first resolved IP address, failing on dual-stack localhost

Important
Why it matters
Connecting to http://localhost:<port> fails if localhost resolves to IPv6 ::1 first while the sidecar is bound only to IPv4 127.0.0.1.
Impact if unaddressed
Standard development and container setups where TEI listens on 127.0.0.1 fail to connect if host is specified as 'localhost'.
Evidence
crates/clio-index/src/http.rs:91-96
Confidence
High

Proposed fix (not yet applied)

Iterate through the SocketAddr iterator from to_socket_addrs() and attempt connect_timeout on each until one succeeds.

04

Dead widening loop and potential duplicate accumulation in SqliteStore::lexical_search

Minor
Why it matters
The loop in sqlite_index.rs::lexical_search is dead code because SQL filtering handles limits directly. If ever reached, it would duplicate results.
Impact if unaddressed
Misleading code structure that mimics dense vector widening where it does not apply.
Evidence
crates/clio-store/src/sqlite_index.rs:148-175
Confidence
High

Proposed fix (not yet applied)

Remove the loop and query directly with limit as parameter.

05

Eager full-bank ID buffering in visible_pages during rebuild sweeps

Minor
Why it matters
Rebuilding indexes for a bank with tens of thousands of items buffers all item IDs in memory at once.
Impact if unaddressed
Unnecessary memory consumption during reindex operations on large banks.
Evidence
crates/clio-index/src/worker.rs:364-377
Confidence
Medium

Proposed fix (not yet applied)

Stream or paginate item IDs lazily during rebuild sweeps.

06

HTTP client reads until EOF without checking Content-Length header

Minor
Why it matters
If a sidecar server sends a full Content-Length response but delays socket shutdown, read_response blocks until the timeout.
Impact if unaddressed
Potential latency spikes if connected to HTTP/1.1 servers that don't immediately close sockets on Connection: close.
Evidence
crates/clio-index/src/http.rs:162-187
Confidence
High

Proposed fix (not yet applied)

Parse Content-Length from response headers and terminate reading once expected bytes have been consumed.
