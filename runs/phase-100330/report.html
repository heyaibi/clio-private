02

Test suite hangs in interactive terminals due to unisolated TTY stdin in setup_usage_errors_exit_2

Critical
Why it matters
Running `cargo test --locked --workspace` or `make check` directly in any interactive terminal (without `</dev/null`) blocks indefinitely on `std::io::stdin()`.
Impact if unaddressed
Freezes standard developer workflows and local test runs for any engineer using an interactive terminal.
Evidence
crates/clio-lib/src/main_tests.rs:61-68. `setup_usage_errors_exit_2` invokes `run(vec!["setup".into()])`. `setup_cli::setup` evaluates `std::io::stdin().is_terminal()`, which is true in terminal shells, prompting `Install type: [1] zero-dependency, [2] airgapped, [3] custom:` and blocking.
Confidence
High

Proposed fix (not yet applied)

Decouple `main_tests.rs` from live process stdin by passing non-interactive flags or routing CLI execution in tests through an injected, non-terminal stream seam.

04

am setup falsely reports 'local services: postgres' for zero-dependency installs

Important
Why it matters
Zero-dependency installs are defined as requiring no Docker and starting no local services, using embedded SQLite. Falsely listing postgres as a local service misleads operators into believing Postgres is running or needed.
Impact if unaddressed
Misleading CLI output that contradicts the documented contract of the zero-dependency install type.
Evidence
crates/clio-lib/src/setup_wizard.rs:198-210. `Plan::local_services()` unconditionally initializes `vec!["postgres"]`. Running `am setup --type zero-dependency ...` reports `local services: postgres`.
Confidence
High

Proposed fix (not yet applied)

In `Plan::local_services()`, only include 'postgres' when `self.install_type != InstallType::ZeroDependency`.

05

Switching install types merges over old credentials instead of removing them, leaking hosted API keys into airgapped configs

Important
Why it matters
Airgapped installations are specified to run with no external keys. If an operator switches from zero-dependency to airgapped, the old API keys remain in deployment.json despite setup stating it replaced existing values.
Impact if unaddressed
Lingering secret keys remain in configuration files for deployments intended to be airgapped.
Evidence
crates/clio-lib/src/setup_config.rs:104-114. `write` only sets fields from `plan.entries()` on top of `rt.deployment_overlay`. An airgapped setup run over a pre-existing zero-dependency config leaves `credentials.embed_api_key` in the file.
Confidence
High

Proposed fix (not yet applied)

When writing a full setup plan, remove provider and credential fields from the deployment overlay that are not configured by the new install type.

06

Incomplete XDG absolute path validation on HOME fallback in default_deployment_path

Minor
Why it matters
The doc comment states that relative base directories are ignored per XDG spec, but while XDG_CONFIG_HOME checks is_absolute(), HOME does not.
Impact if unaddressed
Inconsistent path handling between XDG_CONFIG_HOME and HOME fallbacks.
Evidence
crates/clio-config/src/config/persist.rs:74-77. `XDG_CONFIG_HOME` uses `.filter(|dir| Path::new(dir).is_absolute())`, while `HOME` lacks the `is_absolute()` check.
Confidence
High

Proposed fix (not yet applied)

Add `.filter(|home| Path::new(home).is_absolute())` to the `HOME` lookup in `default_deployment_path`.

Confidence
High

Proposed fix (not yet applied)
