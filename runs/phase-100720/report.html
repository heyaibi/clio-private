Considered and dismissed

  • Possible `-o`/`--output` divergence when the next token starts with a single dash (parse accepts `-x` as a value, main::parse_flags does not): this mirrors the pre-existing long-flag behavior exactly and is not introduced by this change; resolve_output still rejects the bad value with exit 2.
  • Attached short value `-ojson` not accepted: the phase explicitly allows mirroring only the forms the long flag supports (space and `=`), and it is recorded as a known limitation, not claimed as implemented.
  • Per-verb usage lines and the `clio status` usage line do not print `-o`: documented decision consistent with treating `-o` as one global flag documented once in the catalog.
  • Reserved surfaces (`ops`, `mcp`, `retention`, `compose`) ignore `-o` like they ignore `--output`: pre-existing and tracked as open issue #25, out of this phase's scope.
