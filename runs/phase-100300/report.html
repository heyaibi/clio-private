01

Potential double '/v1' path if RERANK_URL contains '/v1' suffix

Minor
Why it matters
Operators accustomed to OpenAI base URLs (like https://api.openai.com/v1) or following zero-deps.md examples might set RERANK_URL with a /v1 suffix, causing requests to target /v1/v1/rerank and fail.
Impact if unaddressed
Configuring RERANK_URL with trailing /v1 results in 404 Not Found from providers unless explicitly configured without /v1.
Evidence
crates/clio-retrieve/src/rerank.rs:191
Confidence
High

Proposed fix (not yet applied)

Strip trailing '/v1' from the base URL before appending '/v1/rerank', or document the strict root domain requirement in .env.example.

02

HttpReranker derived Debug leaks bearer token if printed

Minor
Why it matters
While CohereReranker provides a custom fmt::Debug implementation that redacts bearer tokens, HttpReranker still derives Debug, meaning any debug formatting of the TEI reranker client could expose bearer tokens in logs.
Impact if unaddressed
Low risk for local sidecars which typically do not use bearer tokens, but violates defense-in-depth credential masking for authenticated TEI proxies.
Evidence
crates/clio-retrieve/src/rerank.rs:61-66
Confidence
High

Proposed fix (not yet applied)

Replace #[derive(Debug)] on HttpReranker with a manual fmt::Debug implementation masking self.bearer as '****'.

03

build_reranker_from strictly requires credentials for Cohere provider, blocking keyless local proxies

Minor
Why it matters
Local self-hosted rerank engines (e.g. Infinity, TEI with Cohere API emulation, or local proxies) running Cohere wire format often require no authentication.
Impact if unaddressed
Operators cannot use local Cohere-compatible endpoints without supplying a dummy API key.
Evidence

Confidence
High

Proposed fix (not yet applied)

Allow Optional bearer in build_reranker_from for provider = cohere when the endpoint is unauthenticated local http.
