Confidence
High

05

Pull Loop Permanently Stuck on Unopenable or Corrupted Ciphertext (Bypassing DLQ Quarantine)

Important
Why it matters
If a client cannot decrypt an encrypted payload (wrong key, bad ciphertext, or tampering), pull fails with an unhandled error instead of quarantining the mutation to dead-letter.
Impact if unaddressed
The pull pipeline is permanently wedged. Because the mutation is never written to sync_dead_letter, the operator cannot call ack_skip to unfreeze the pull cursor.
Evidence
crates/clio-sync/src/client.rs:368 calls let bytes = key.open(cipher)?; in decrypt_for_apply. Any decryption error bubbles up through ?, terminating pull_bank without recording a dead-letter row.
Confidence
High

Proposed fix (not yet applied)

Catch key.open() errors in decrypt_for_apply, quarantine the mutation into sync_dead_letter using quarantine(), and return Ok(None) so the pull cursor safely freezes and can be ack-skipped.
