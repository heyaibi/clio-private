01

prefer_consolidated suppresses raws claimed by a parent that is NOT in the returned page

Important
Why it matters
The phase promises to drop raw items only when their consolidated parent is also returned, and that coverage does not shrink. The code suppresses a raw whenever any parent in the fetched candidate list claims it, even when that parent is truncated out of the returned page, so the raw content disappears with no consolidated replacement.
Impact if unaddressed
Silent recall loss under prefer_consolidated=true whenever a parent ranks below the limit/budget boundary but its raw sources rank inside it. The returned page differs from the documented contract and from a page-only implementation.
Evidence
crates/clio-retrieve/src/dedup.rs:212-231 builds `claimed` from every parent in `filtered` before truncation and then retain()s the raws; crates/clio-retrieve/src/finalize.rs:85-90 truncates to the page afterwards. Phase doc roadmap/phase-100270-consolidated-recall-dedup.md:176 says 'any returned parent' and :33 says the parent 'is also returned'.
Confidence
High

Proposed fix (not yet applied)

Compute the page first (or the set of parent ids that actually survive select_page over the deduped/scope-filtered candidates) and only suppress raws whose id is claimed by a parent present in that returned page; recompute after truncation or make suppression page-aware.

02

consolidated_only never returns canonical consolidation outputs

Important
Why it matters
Task 1 defines a consolidated_item as a canonical consolidation output OR a hub-distilled semantic item. The eligibility predicate recognizes only the hub_distill marker, so the primary consolidated unit class is excluded from the scope preset.
Impact if unaddressed
On a bank whose only consolidation is canonical (the default ingest path, ingest.rs admit_canonical_units), consolidated_only returns empty with scope_empty=true even though consolidated units exist. The feature headline ('return consolidated knowledge instead of every raw fact') is only half delivered.
Evidence
crates/clio-retrieve/src/dedup.rs:90-92 (only source_ref==HUB_DISTILL_SOURCE_REF); canonical path stores source_ref = unit.source_refs.join(",") at crates/clio-write/src/ingest.rs:239-243 with chunk provenance in AdmittedLeaf, not on the item; phase doc :144.
Confidence
High

Proposed fix (not yet applied)

Add a durable marker for canonical consolidation outputs (e.g. a source_ref/kind convention or an item flag) and extend is_consolidated_item to include it; until then, document explicitly that consolidated_only is empty for canonical-only banks and treat it as a named limitation, not a passing AC.
