01

Ranking-env co-activation knobs are stored but consumed by no production path

Important
Why it matters
The phase Goal and AC-100130-08 present association knobs as operator-tunable without code changes. In fact nothing reads RankingEnv.coactivation when building the retriever, so ranking_env_set(eta=...) has no effect on reinforcement or decay.
Impact if unaddressed
Operators can change eta/half_life/w_min in config and observe no behavioral change, silently. The tests pass only because they set the policy object directly.
Evidence
crates/clio-retrieve/src/hybrid.rs:83-86; crates/clio-store/src/assoc.rs:47-51; grep: from_coactivation/set_assoc_policy have no non-test callers; crates/clio-retrieve/src/assoc_tests.rs:188-202.
Confidence
High

Proposed fix (not yet applied)

Construct AssocPolicy from the live RankingEnv.coactivation at retriever construction (or in the retrieve handler), and add a test that patches eta via ranking_env and observes the changed growth step on retrieve.

02

§7.4.5 derivative-decision log failure is silently swallowed

Important
Why it matters
requirement.md §7.4.5 states the anonymized-derivative determination MUST be affirmatively logged per item at distillation time. The code discards the log result.
Impact if unaddressed
A distilled item can be admitted and retained with no durable record of the derivative decision, so the compliance MUST is not guaranteed.
Evidence
crates/clio-write/src/hub_distill.rs:361-368.
Confidence
High

Proposed fix (not yet applied)

Propagate record_assoc_audit's error from distill_hub so the distillation fails (or reports degraded) when the decision cannot be logged.

03

expand_graph ignores min_weight for explicit edges and the comment is inaccurate

Important
Why it matters
Phase Task 5 requires expansion to add neighbors with w_eff >= min_weight. Explicit edges are added at any weight, unlike associations/graph_query, so weak explicit links can pull unrelated items into results.
Impact if unaddressed
Inconsistent filtering between tools; a 0.0-1.0 weight explicit edge below w_min is still expanded, defeating the min_weight bound.
Evidence
crates/clio-retrieve/src/assoc_graph.rs:267-289 and :271 comment; crates/clio-retrieve/src/assoc.rs:138-139.
Confidence
High

Proposed fix (not yet applied)

Apply `eff < min` in expand_ids for both kinds, or explicitly document and test that sticky explicit edges intentionally bypass min_weight; fix the misleading comment.
