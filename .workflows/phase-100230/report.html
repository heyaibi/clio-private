02

MCP ops error and repair-detail messages are not credential-redacted, unlike the CLI

Important
Why it matters
§4.9.7 forbids returning unmasked credentials from diagnose/doctor/repair surfaces. The CLI author added redact() precisely because driver errors can embed connection URLs, but the MCP path and the repair action details do not apply it, so the same error leaks over MCP what the CLI hides.
Impact if unaddressed
A Postgres connection error could surface a URL with an embedded password in an MCP tool result (content/structuredContent) or in a repair action detail printed by CLI --confirm.
Evidence
crates/clio-mcp/src/ops_tools.rs:145-158 copies err.message verbatim into message and findings; crates/clio-ops/src/repair.rs:280 and :325 interpolate raw {e} into ActionOutcome.detail; crates/clio-lib/src/ops_cli.rs:283-290 is the only redaction helper and is CLI-only.
Confidence
Medium

Proposed fix (not yet applied)

Promote a single shared redactor (URL userinfo stripping) and apply it in error_envelope and to every ActionOutcome.detail built from an error.

03

Bank-scoped reindex runs whole-store orphan cleanup

Important
Why it matters
The public reindex contract says a bank or the whole store can be targeted. The orphan-cleanup step inside the sweep ignores the scope and deletes derived rows in every bank, so a scoped operation mutates data outside its scope (and reruns redundantly once per bank on whole-store runs).
Impact if unaddressed
An operator reindexing one bank can drop orphan vectors/lexical docs/queue rows belonging to other banks, including banks the caller was not authorized for.
Evidence
crates/clio-index/src/rebuild.rs:84-101 calls index.cleanup_orphans() inside the per-scope loop; the trait method takes no bank (crates/clio-store/src/index_store.rs:141-145) and the SQLite implementation deletes globally (crates/clio-store/src/sqlite_index.rs:333-349).
Confidence
High

Proposed fix (not yet applied)

Run cleanup once per call and, when a bank scope is given, either skip cleanup or add a bank-filtered cleanup so scoped reindex never touches other banks.

04

Shared-bank permission is bypassed by calling reindex without a bank

Important
Why it matters
The deployment gate for the cross-agent `shared` namespace is meant to block all access unless enabled. reindex calls resolve_ctx (which checks the default/args bank) but then passes the raw bank arg to reindex; when omitted, the rebuild expands to every indexable bank, including `shared`.
Impact if unaddressed
A caller on a deployment with the shared bank disabled can still mutate the shared bank's derived index state by omitting `bank`.
Evidence
crates/clio-mcp/src/ops_tools.rs:109-122 (resolve_ctx result discarded; bank: opt_str(args,"bank")), crates/clio-mcp/src/runtime.rs:278-302 (only gate is bank == shared), crates/clio-index/src/rebuild.rs:75-78 (None -> indexable_banks()).
Confidence
Medium

Proposed fix (not yet applied)

Use the resolved context bank when args omit one, or reject a bank-less reindex/repair when the deployment has the shared bank disabled, or exclude the shared bank from the default scope.
