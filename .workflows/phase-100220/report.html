01

Live import executes un-batched store mutations during `Planner::run`, violating transactional rollback guarantees

Critical
Why it matters
If import fails partway through execution, partial writes remain committed to the database with no rollback mechanism, causing inconsistent state and corrupted banks.
Impact if unaddressed
Violates §5 Task 2 and §10 rollback requirements; corrupts state on mid-batch failure.
Evidence
crates/clio-compliance/src/import.rs:138 calls planner.run()?, which executes direct mutations in import_apply.rs:151,271,272,286,370,390 and import_rows.rs:250,283 before batch commit.
Confidence
High

Proposed fix (not yet applied)

Defer all mutations until planning validates the entire bundle, and execute all writes within an atomic batch or transaction.

03

Ciphertext backup import invokes `Store::put_item`, double-encrypting ciphertext and discarding all item metadata

Important
Why it matters
Restoring a ciphertext backup produces unusable rows: ciphertext is re-encrypted with local KMS DEK, item columns are wiped, and get_memory_item fails.
Impact if unaddressed
ciphertext_backup round-trip claims are broken; restored data is unreadable.
Evidence
crates/clio-compliance/src/import_apply.rs:260-287 passes opaque ciphertext to Store::put_item, which encrypts it again and inserts dummy episodic rows in envelope_persist.rs:49-55.
Confidence
High

Proposed fix (not yet applied)

Persist OpaqueItem rows directly to items table preserving metadata and writing pre-encrypted content_ciphertext without re-encryption.

04

`sort_entity_arrays` omits `ComplianceTombstoneView`, breaking canonical ordering and cross-backend checksum equivalence

Important
Why it matters
Tombstone arrays are not canonically ordered, causing checksum mismatches on cross-backend import and non-deterministic bundle hashes.
Impact if unaddressed
Breaks Appendix §4 canonical JSON checksum verification when tombstones are present.
Evidence
crates/clio-compliance/src/bundle.rs:276-288 only inspects id, key, and as_of; ComplianceTombstoneView has none of these, leaving tombstones in raw database order (which differs between SQLite and Postgres).
Confidence
High

Proposed fix (not yet applied)

Add tombstone comparator fields (subject_hash, item_id_hash, request_id) to sort_entity_arrays and align SQLite/Postgres tombstone SQL order.
