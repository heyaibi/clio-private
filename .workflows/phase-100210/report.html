01

Primary key collision in append_log on duplicate target item IDs crashes clean

Important
Why it matters
append_log generates entry IDs as format!("hlg-{}-{}", args.batch_id, target.item_id). If a target item ID appears multiple times in args.targets, the second insert into hygiene_audit_logs violates the primary key constraint.
Impact if unaddressed
In dry-run mode, clean fails with an unhandled database error instead of returning counts. In confirmed mode, an unhandled database error bubbles up via ? after previous mutations were committed, leaving mutations applied without structured abort reporting.
Evidence
crates/clio-hygiene/src/clean.rs:301: id: format!("hlg-{}-{}", args.batch_id, target.item_id); verified with sqlite UNIQUE constraint failed on duplicate insertion.
Confidence
High

Proposed fix (not yet applied)

Include the target iteration index in the generated log ID (format!("hlg-{}-{}-{index}", args.batch_id, target.item_id)) or deduplicate target item IDs during preflight validation.

02

Preflight validation for confirmed discard reason bypasses CleanAction::Keep

Important
Why it matters
Line 165 only checks args.action == CleanAction::Discard when validating non-empty reason. When action is Keep, individual targets can resolve to Discard.
Impact if unaddressed
If an operator calls confirmed clean with keep and an empty reason, validation passes initially, but when the first target resolved to Discard is processed, store.discard_item fails, aborting the batch mid-flight after earlier targets were mutated.
Evidence
crates/clio-hygiene/src/clean.rs:165: if args.confirm && args.action == CleanAction::Discard && args.reason.trim().is_empty()
Confidence
High

Proposed fix (not yet applied)

Extend preflight check to verify non-empty reason if args.action == CleanAction::Discard || (args.action == CleanAction::Keep && args.targets.iter().any(|t| t.suggested_action.as_deref() == Some("discard"))).
