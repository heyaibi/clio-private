Generating IDs as format!("trp-{}", args.timestamp) and format!("itm-{}", args.timestamp) causes primary key collisions when multiple triples are created at the same timestamp tick.
Impact if unaddressed
Concurrent or batched triple writes fail with database duplicate key errors.
Evidence
crates/clio-write/src/triple.rs:136-137: `let edge_id = format!("trp-{}", args.timestamp); let item_id = format!("itm-{}", args.timestamp);`
Confidence
High

Proposed fix (not yet applied)

Include a random suffix, nano-timestamp, or monotonic counter (e.g., format!("trp-{}-{}", args.timestamp, nonce)) to guarantee uniqueness.

06

Flawed 'current' semantics when `as_of` is omitted in `triple_query`

Minor
Why it matters
Omitting as_of on the valid axis simply checks valid_until.is_none(). Future facts that are not yet valid (valid_from > now) are improperly returned as currently valid.
Impact if unaddressed
Callers querying current state receive facts that are not yet effective.
Evidence
crates/clio-store/src/triple_map.rs:79: `TimeAxis::Valid => t.valid_until.is_none()`
Confidence
High

Proposed fix (not yet applied)

When as_of is None, default to the current timestamp (now) so that valid_from <= now < valid_until.

07

Minor
Why it matters
An edge with a defined future expiration (valid_until set) that is still transactionally active (tx_until is null) is skipped by the open-edge supersession query.
Impact if unaddressed
Conflicting edges can remain open simultaneously in transaction time if an earlier edge had a bounded valid_until.
Evidence
crates/clio-store/src/sqlite_triple.rs:95 and crates/clio-store/src/postgres_triple.rs:92: `WHERE ... AND valid_until IS NULL AND tx_until IS NULL`
Confidence
High

Proposed fix (not yet applied)

Query open edges by `tx_until IS NULL` and close overlapping edges accordingly.
