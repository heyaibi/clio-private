01

AGENTS.md module header specification violation in three newly introduced Rust files

Important
Why it matters
AGENTS.md requires every Rust source file to have an exact module header structure ending with '//! Keep this module focused on <a single responsibility>.'. Missing this line violates the normative repository code standard.
Impact if unaddressed
Code style and consistency violation in production Rust crates (clio-store and clio-mcp).
Evidence
crates/clio-store/src/postgres_inspect.rs:18-19, crates/clio-store/src/sqlite_inspect.rs:18-19, crates/clio-mcp/src/read_retrieve.rs:19-21 omit the required closing line.
Confidence
High

Proposed fix (not yet applied)

Append `//! Keep this module focused on <a single responsibility>.` (with appropriate responsibility wording) to the header doc comments of postgres_inspect.rs, sqlite_inspect.rs, and read_retrieve.rs.

Minor 02

Worth considering. Unlikely to change the substantive result.

02

Schema parameter omission for persona_get and compose_context in published tool_schema pack

Minor
Why it matters
All published MCP tool definitions enforce additionalProperties: false. If a handler parses parameters that are not defined in the schema, strict MCP client validators will reject client calls attempting to supply those parameters.
Impact if unaddressed
Clients passing budget_tokens to persona_get or as_of/time_axis/expand_graph to compose_context will fail JSON Schema validation.
Evidence
crates/clio-mcp/src/schema_read_defs.rs:127-131 has empty props for persona_get, but read_tools.rs:161-163 reads budget_tokens. Similarly, schema_read_defs.rs:108-116 omits as_of/time_axis/expand_graph for compose_context, while read_retrieve.rs:134-136 extracts them.
Confidence
High

Proposed fix (not yet applied)

Add the optional property definitions to schema_read_defs.rs (budget_tokens for persona_get; as_of, time_axis, expand_graph for compose_context), or remove their extraction from the handler if intentionally unsupported over MCP.
