01

Point-in-time triple trajectory truncates before the as_of filter

Important
Why it matters
temporal_history is the NFR-4 point-in-time read. When a (subject, predicate) has more versions than the hard limit, the SQL LIMIT is applied to the oldest rows first and as_of is filtered afterward, so a query 'as of date X' can omit the version that was current at X and answer with an older state.
Impact if unaddressed
Silent wrong point-in-time answer whenever version count > limit (default 20, max 200). Untested because T100150-08 uses only 2 versions and the limit test uses no as_of.
Evidence
crates/clio-store/src/sqlite_history_read.rs:282-289 orders `ORDER BY tx_from, id LIMIT ?4` (ascending, oldest first); crates/clio-store/src/postgres_history_read.rs:196-207 same; crates/clio-history/src/temporal.rs:248-263 filters `valid_from <= as_of` / `tx_from <= as_of` client-side after the fetch.
Confidence
High

Proposed fix (not yet applied)

Push the as_of predicate into the SQL (add as_of/axis parameters to triple_history, or fetch the newest N at/under as_of via a subquery) so filtering happens before limiting; add a regression test with 3+ versions, limit=2, and as_of beyond the limit that asserts the entry current at as_of is returned.
