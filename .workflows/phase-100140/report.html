02

Pre-admission database mutation in persona_observe_preference

Important
Why it matters
When a candidate preference fails create-time admission, nothing should be written to the database. Currently, ensure_continuous_declaration commits the attribute schema before admission evaluates the candidate.
Impact if unaddressed
Unadmitted candidate keys permanently pollute attribute_schemas and are locked into continuous update_rule, blocking subsequent persona_put_stable discrete writes for those keys.
Evidence
crates/clio-persona/src/observe.rs:120, 126-137: `ensure_continuous_declaration(args)?;` is executed before `run_create_admission(args)?;`. If admission returns rejected, the schema write is not rolled back.
Confidence
High

Proposed fix (not yet applied)

Before admission in persona_observe_preference, only inspect if an existing schema is discrete (rejecting if so). Defer registration of new continuous schema until after run_create_admission passes.
