Impact if unaddressed

High

Proposed fix (not yet applied)

Uncheck 'Verification is completed' and 'Required approval is obtained' until the adversary/human rows complete; or relabel them as 'self-verification completed; independent verification pending'.

02

retrieve() can exceed its requested budget_tokens for a single oversized hit

Important
Why it matters
Task 4 requires retrieve to honor budgets when trimming the returned pack. The `&& !hits.is_empty()` guard means the first candidate is admitted even when it alone is larger than the budget, so the optional budget is a soft floor, not a cap.
Impact if unaddressed
A caller passing a small budget_tokens can receive a hit whose estimated_tokens exceeds it. The PR-1 injection bound is still safe because compose re-truncates in pack_memory (compose.rs:289-316), so this is a retrieve-contract issue, not an injection leak.
Evidence
crates/clio-retrieve/src/finalize.rs:50-55: `if let Some(budget) = args.req.budget_tokens && estimated_tokens + tokens > budget && !hits.is_empty() { break; }`. No test exercises a single hit larger than the budget (budget_tokens_trims_returned_hits uses two 8-token hits with budget 8).
Confidence
High

Proposed fix (not yet applied)

Either drop/skip a candidate that alone exceeds the remaining budget, or explicitly document and test that at least one hit is always returned as a deliberate behavior with its budget consequence stated.

04

Important
Why it matters
requirement.md:681 says the intent gate's false-negative rate SHALL be tracked separately from, and held to a stricter bound than, its false-positive rate. evaluated/skipped counters cannot express either rate because there is no ground truth attached to a decision.
Impact if unaddressed
The system cannot currently demonstrate the stricter false-negative bound the spec demands; a gate that skips many memory-needed turns looks identical to a well-calibrated one in metrics.
Evidence
intent.rs:90-123 (GateMetrics: evaluated, skipped only); intent_tests.rs:108-116 asserts only those two counters. No false_negative/false_positive symbol exists anywhere in crates/.
Confidence
High

Proposed fix (not yet applied)

Add a labeled evaluation hook that records expected_needed vs decision (FN/FP counters) and a documented stricter FN bound, or explicitly scope this metric to a later offline-evaluation phase and say so in the phase file.

Impact if unaddressed
A future change that adds real work to the gate (e.g. a classifier call) could still pass this test up to ~50 ms per call.
Evidence

Confidence
High

Proposed fix (not yet applied)
